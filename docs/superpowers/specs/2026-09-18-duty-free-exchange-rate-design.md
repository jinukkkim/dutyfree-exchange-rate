# 면세점 환율 기록·공개 사이트 — 설계

작성 2026-09-18. 도메인 사실·용어·법령 근거는 `docs/domain-reference.md` 에 있고,
이 문서는 그것을 전제로 **무엇을 어떻게 만들 것인가**만 다룬다.

---

## 1. 목적

한국 면세점 **적용환율**을 매일 기록·공개하고, **면세점 기준환율** 변경 이력을
아카이브한다.

### 왜 필요한가

세 가지 근거가 있고 전부 측정되었다 (2016-01-04 ~ 2026-09-17, 2,637 영업일).

1. **내일 적용환율은 이미 확정되어 있다.** 오늘 08:00 고시가 내일 적용환율이다
   (보세판매장 고시 §3④1). 예측이 아니라 사실이므로 "오늘 살까 내일 살까"에
   확정적으로 답할 수 있다.
2. **뉴스 환율로 판단하면 47.1% 틀린다.** 시장 방향과 면세점 방향의 부호가
   반대인 날이 1,205/2,560일. 두 숫자가 이틀 떨어진 서로 다른 날을 가리키기
   때문이며, 구조가 만드는 필연이다.
3. **기준환율 기록이 어디에도 없다.** 면세점 공지에도 없고 언론 보도만 있으며
   그 보도끼리 충돌한다. 국산품에 10% 수준의 가격 차이를 만드는 변수다.

하루 기다림의 값어치: 중앙값 3.5원, 36%의 날이 5원 이상, 10%의 날이 10원 이상
(최대 42.3원). $300 구매 기준 각각 약 1,050원 / 1,500원+ / 3,000원+.

### 기존 서비스

- **dutyfreemania.com** — 현역 유일. 제안은 옳으나 Google Auto Ads 가 본문을
  밀어내고(1512px 화면에서 환율표가 y=680), HTTPS 미지원, 이력 1개월.
- **devremon.byus.net/dutyfree** — 사실상 사망. `chart.json` 이 응답에 28초 걸리고
  `{"date":"...","rate": }` 로 값이 빈 깨진 JSON을 내보내 차트가 안 그려진다.
  **조용한 파싱 실패**의 교본이며, 이 설계의 실패 감지 요구사항 대부분이 여기서 왔다.

## 2. 범위

### 포함

- 적용환율 일별 시계열 (2016년 이후 백필 + 매일 수집)
- 오늘·내일 적용환율과 차이, 금액 환산
- 면세점 기준환율 변경 이력 (수동 기록)
- 두 환율이 무엇인지에 대한 설명

### 제외 (v1)

- **분석·판정** — "지금이 최근 1년 중 하위 X%" 류. 사실을 정확히 보여주는 데 집중한다.
- **예측** — 모레 이후. 내일은 확정이므로 예측 대상이 아니다.
- **가격 패널 자동 크롤링** — 기준환율 역산용. 연 3~4회 이벤트에 상시 크롤러와
  헤드리스 브라우저를 v1에 넣지 않는다. 필요해지면 §7 의 수동 확인을 승격한다.
- **광고** — 원래 동기가 광고 과다였다. 넣지 않는다.
- **USD 외 통화** — 국내 면세점 정가는 달러다.
- **회원·알림·계정**

## 3. 아키텍처

수집과 호스팅을 분리한다. 사이트는 런타임에 서버를 건드리지 않는다.

```
KST 09:00   VM 크론 (exhibition-traffic 과 같은 박스)
   ├─ smbs XML 수집 (최근 10일 겹쳐 조회)
   ├─ 신세계몰 todayRate 교차검증
   ├─ 무결성 통과 시에만 data/*.csv 갱신
   ├─ git commit && push
   └─ healthchecks.io ping
                ↓
           GitHub  (= 원격 백업 + 감사 이력 + 실패 Issue)
                ↓ webhook
           Vercel 빌드 (Vite 정적) → CDN
```

### 선택 근거

| 결정 | 이유 |
|---|---|
| 정적 사이트 | 하루 1회 갱신, 전량 40KB 수준. 동적 서버가 할 일이 없다 |
| Vercel | TLS 자동. duckdns·인증서 갱신·Caddy 설정이 전부 사라진다 |
| 수집만 VM | GitHub Actions 예약 워크플로는 부하 시 지연되고 저활동 리포는 60일 후 자동 비활성화된다. 몇 년을 쌓는 프로젝트에 부적합 |
| 데이터를 git에 | 백업·감사이력·diff 가 공짜. SQLite 는 이 규모에 불필요 |
| 사이트가 VM 무의존 | 박스가 죽어도 사이트는 마지막 데이터로 계속 뜬다. devremon 의 반대 |

**exhibition-traffic 에서 가져오는 것**: 커밋·브랜치·PR 규약, CI 형태(pytest + vitest),
주석 문화, 모든 스케줄에 KST 명시, 손으로 그린 인라인 SVG 차트, 박스 한 대.

**가져오지 않는 것**: Redis, SSE, FastAPI, systemd 유닛, duckdns, SQLite, OCI 백업.
전부 288 polls/day 가 정당화하던 것이고 1 poll/day 는 정당화하지 못한다.

### 스택

- 수집기: Python 3.12 (표준 라이브러리 + httpx). 프레임워크 없음
- 프론트: React 18 + TypeScript + Vite + Tailwind. 차트 라이브러리 없이 인라인 SVG
- Vercel Hobby (비상업적 조건. 광고를 붙이면 위반이므로 그때는 Cloudflare Pages)

## 4. 데이터 모델

### `data/rates.csv`

```
fix_date,rate,method,source,collected_at
2026-09-16,1353.3,MAR,smbs,2026-09-17T09:00:12+09:00
2026-09-17,1368.3,MAR,smbs,2026-09-18T09:00:09+09:00
```

| 필드 | 설명 |
|---|---|
| `fix_date` | **고시일**. 적용일이 아니다 |
| `rate` | 매매기준율. USD 는 0.1원 단위 (2,637건 전수 확인) |
| `method` | `MAR` \| `TWAP`. 2027-01-01 방법론 단절을 데이터가 스스로 들고 있게 한다 |
| `source` | `smbs` \| `smbs+ssgdfs` (교차검증 통과 여부) |
| `collected_at` | KST ISO8601 |

**적용일은 저장하지 않고 파생한다.** 고시일 D 의 값은 D+1 부터 다음 고시일까지
적용된다. 이렇게 두면 주말·공휴일 이월이 저장이 아니라 규칙이 되고,
**공휴일 달력을 관리할 필요가 없다.** 보세판매장 고시 §3④1 의
"전일(최종 고시한 날을 말한다)" 이 바로 이 구조다.

검증: 고시 2026-09-11(금) 1,338.2 → 적용 09-12·13·14 전부 1,338.2 (실측 일치).

### `data/base_rates.csv`

```
operator,effective_date,rate,status,source_url,note
lotte,2026-07-08,1500,confirmed,https://...,
shinsegae,2026-07-09,1500,confirmed,https://...,
lotte,2026-09-09,,unconfirmed,,값 미확정
```

`operator` 는 `lotte` \| `shilla` \| `shinsegae` \| `hyundai`.
`status` 는 `confirmed` \| `unconfirmed`. 미확정을 **기록하되 구분**한다 —
비워두면 구멍이 남고, 추정치를 확정인 척 넣으면 기록이 오염된다.

초기 시드는 `docs/domain-reference.md` §4 에 있으나 2차 보도끼리 충돌한다.
원문 기사를 읽어 확정하는 것이 구현 작업에 포함된다.

### `data/meta.json`

```json
{ "base_rates_verified_at": "2026-09-17" }
```

수동 운영의 위험은 조용히 낡는 것이다. 마지막 확인일을 화면에 띄우면 낡음이 보인다.

## 5. 수집기

### 실행

KST 09:00 크론 1회 (고시 08:00 + 1시간 여유). 값은 하루 중 바뀌지 않으므로
재수집은 불필요하고, 실패 시 재시도만 건다.

### 절차

1. smbs XML 에서 **최근 10일** 조회
   ```
   http://www.smbs.biz/ExRate/StdExRate_xml.jsp?arr_value=USD_<from>_<to>
   ```
   EUC-KR, `<set label='26.09.17' value='1368.3' />` 형태. 하루치만 받지 않고
   겹쳐 받는 이유: 장애·공휴일로 빠진 날이 자동으로 메워지고, 과거 값이 정정되면
   그때 드러난다.
2. 신세계 메인에서 `<span class="todayRate">` 파싱 → 오늘 적용환율
3. **교차검증**: 신세계의 오늘 값 == smbs 의 직전 고시일 값
4. 무결성 검사 통과 시에만 CSV upsert → 변경분만 commit & push
5. healthchecks.io ping

### 무결성 검사

| 검사 | 실패 시 |
|---|---|
| 파싱 결과 0건 또는 값 비어 있음 | 중단. **빈 행은 절대 쓰지 않는다** |
| 값이 500~5,000원 범위 밖 | 거부 |
| 전일 대비 100원 초과 변동 | 기록하되 플래그 (실측 최대 42.3원) |
| smbs ≠ 신세계 | smbs 채택 + 플래그 + Issue |

**1차 소스(smbs) 실패는 중단, 검증 소스(신세계) 실패는 진행 + 경고.**
검증 수단을 잃었다고 기록을 멈추면 검증이 수집을 인질로 잡는다.

### 백필

동일 엔드포인트로 2016-01-04 이후 2,637 영업일을 단일 요청(159KB)으로 받을 수 있다.
1회성 스크립트로 처리하고 이후 일별 수집에 맡긴다.

## 6. 화면

첫 화면이 전부다. 원래 불만이 "눈에 안 들어온다" 였다.

```
┌──────────────────────────────────┐
│  면세점 적용환율                  │
│                                  │
│      오늘        내일            │
│    1,353.30   1,368.30           │
│                  ▲ 15.00         │
│                                  │
│  내일은 오늘보다 비쌉니다.        │
│  $300 기준 약 4,500원 더.         │
│                                  │
│  ※ 내일 값은 예측이 아니라        │
│    오늘 08:00 확정된 고시치입니다. │
└──────────────────────────────────┘
        ↓
   시계열 차트 (기간 선택)
   기준환율 이력 + 마지막 확인일
   두 환율 설명
   제보 링크
```

### 원칙

1. **첫 화면은 두 숫자와 한 문장.** 광고·캐러셀·지점 목록은 없거나 맨 아래.
2. **차이를 돈으로 환산.** "15원"은 크기가 안 잡히고 "$300 기준 4,500원"은 잡힌다.
   기준 금액은 사용자가 바꿀 수 있게 한다.
3. **"확정"을 명시.** 사람들은 "내일 환율"을 예보로 오해한다. 이미 고시된
   사실이라는 한 줄이 행동을 바꾼다.
4. **모바일 우선.** 환율 확인은 폰에서 일어난다.
5. 표시 형식은 보세판매장 고시 §3④2 를 따라 **소수점 2자리** (`1,353.3` → `1,353.30`).

### 문구

`docs/domain-reference.md` 의 용어표를 따른다. 화면 어디에도 **"고시환율"** 은 쓰지
않는다(은행 고시환율과 혼동). 기준환율이 나오는 자리엔 항상
**"면세점 기준환율(국산품용)"** 로 적어 매매기준율과 구분한다.

### 제보

외부 폼 링크 하나(Tally 또는 Google Forms). 백엔드 없음. 필수 필드:

```
면세점 · 상품명 · 예전 달러가 · 지금 달러가 · 확인 날짜
```

이 다섯이면 `기준환율_new = 기준환율_old × (예전가 ÷ 지금가)` 가 계산된다.
제보가 인상이 아니라 검증 가능한 데이터 포인트로 들어온다.

## 7. 실패 감지와 운영

원칙: **침묵이 건강을 뜻하게 만든다.** 아무 소리가 없을 때 "정상"과 "죽었는데
조용함"이 구분되지 않으면 안 된다.

### 실패 모드

| 실패 | 감지 | 대응 |
|---|---|---|
| smbs 엔드포인트 사망·변경 | HTTP 오류 / 파싱 0건 | 커밋 없음 + Issue |
| 조용한 파싱 실패 | 항목 0 또는 빈 값 | 같음 |
| 값 비정상 | 범위 밖 | 거부 + Issue |
| 값 급변 | 전일 대비 100원 초과 | 기록 + 플래그 |
| 교차검증 불일치 | smbs ≠ 신세계 | smbs 채택 + Issue |
| 신세계 마크업 변경 | `todayRate` 파싱 실패 | 수집 진행 + 경고 |
| 크론 미실행 | 데드맨 스위치 | 외부 이메일 |
| git push 실패 | 종료코드 | Issue |
| Vercel 빌드 실패 | Vercel 기본 알림 | — |
| 데이터 정체 | 마지막 고시일 7일 초과 | 사이트 배너 + Issue |
| 기준환율 낡음 | `meta.json` 확인일 | 사이트 표시 |

### 데드맨 스위치

죽은 크론은 스스로 신고하지 못한다. 성공 시 신호를 보내고 신호가 끊기면 외부가 알린다.

```bash
curl -fsS -m 10 "$HEALTHCHECK_URL" > /dev/null
```

ping 의 의미는 **"수집기가 정상 동작했다"** 이지 "새 고시가 있었다"가 아니다.
주말·공휴일에도 ping 한다. 데이터 정체는 별개 신호로 본다.

**7일 임계값**: 한국 최장 연휴가 설·추석 + 주말로 5일 안팎. 이 덕분에 공휴일
달력을 관리하지 않아도 된다 — 영업일을 판정하는 대신 "너무 오래 조용한가"만 본다.

### 사이트가 스스로 신선도를 판정한다

페이지가 `collected_at` 을 현재 시각과 비교해 오래됐으면 배너를 띄운다.

```
⚠ 이 데이터는 2026-09-11 이후 갱신되지 않았습니다.
```

서버·헬스 엔드포인트·업타임 모니터 없이 동작한다. 데드맨 스위치는 **운영자에게**,
배너는 **방문자에게** 알린다. 낡은 데이터를 멀쩡한 척 보여주는 것이 이 분야에서
제일 나쁜 실패다.

### 기준환율 운영 (수동)

연 3~4회이므로 운영자가 직접 기록한다. 관리자 UI 없이 `data/base_rates.csv` 를
고쳐 커밋한다 — **git 이 관리자 화면**이고 이력·작성자·시각이 공짜로 남는다.

보조 채널은 사용자 제보(§6)다. 자동 탐지가 없으므로 놓칠 수 있고, 그래서
`meta.json` 의 확인일을 사이트에 노출해 **낡음이 보이게** 한다.

### 기록 표면

| 표면 | 담당 |
|---|---|
| journald (VM) | 수집기 실행 로그 |
| GitHub Issues | 사람이 처리할 실패 |
| git log | 데이터 변경 이력 |

별도 백업은 없다. 데이터가 git 에 있으므로 GitHub 와 모든 클론이 백업이고,
스냅샷과 달리 변경 이력까지 남는다.

### 테스트

pytest 로 돌리되 픽스처·플러그인 없이 `test_collect.py` 파일 하나.

1. **주말 이월** — 고시 09-11(금) 1,338.2 → 적용 09-12·13·14 전부 1,338.2
2. **D-1 매핑** — 고시 09-17 → 적용 09-18
3. **빈 값 거부** — devremon 식 `value=''` 입력 시 커밋하지 않고 예외

1번이 가장 값어치 있다. 고시일→적용일 변환은 조용히 틀리기 쉽고, 틀리면
**매일 하루씩 어긋난 값**을 몇 달간 기록하게 된다.

### 타임존

모든 스케줄과 날짜 계산에 `Asia/Seoul` 을 명시한다. 크론이 UTC 로 해석되면
KST 09:00 이 18:00 이 되고, 날짜 경계가 밀리면 고시일 라벨이 통째로 하루씩 어긋난다.
